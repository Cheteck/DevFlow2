# Session Report — 2026-09-16 — Audit dogfeeding & hardening production

## Objectif

Auditer le dogfeeding pour identifier les blocages production et améliorer MosaiX
de façon générique plutôt que par workarounds spécifiques.

## Classification appliquée

- **Dogfeeding** : corrigé dans `apps/*` / `src/*`.
- **Mauvais usage MosaiX** : rebranché sur l'API native existante.
- **Lacune framework** : amélioré dans `packages/*` de façon réutilisable.

## Lacunes framework corrigées (génériques)

1. **JWT tripliqué** — `identity-controller`, `jwt-auth-middleware`, `gateway.validateJwt`
   réimplémentaient HMAC-SHA256. Nouveau `@mosaix/auth` `JwtService`
   (`packages/auth/src/jwt-service.ts` : `sign`/`verify`/`resolveJwtSecret`) ;
   `gateway.validateJwt` délègue désormais au service.
2. **OTLP drop-on-failure** — `flush()` vidait le batch même en échec, sans timeout
   ni retry. Ajout `timeoutMs`/`maxRetries`/`configure()`, backoff exponentiel,
   préservation du batch (borné à 1000 spans). `Gateway` applique enfin
   `telemetryOptions` (endpoint/headers/batchSize) au singleton.
3. **Outbox** — `OutboxWorker` accédait à `engine["repo"]` (hack privé), sans timeout,
   sans idempotence, sans backoff. Ajout `markRetry`/`markAsFailed` sur
   `TransactionalOutboxEngine`, timeout par handler, garde d'idempotence,
   backoff. `OutboxDaemon` : `onError`, jitter, `unref()`, plus d'erreurs avalées
   silencieusement.
4. **SDK** — `feature()` retournait toujours le défaut (mock silencieux) ;
   `ulid()` utilisait `Math.random` ; `logger` jetait sans app active ;
   `cache()` global non injectable. Ajout `setFeatureFlagOverride`,
   `randomBytes` pour ULID, logger tolérant, `setCacheWrapper`/`resolveCache`.
5. **CORS** — défaut `["*"]` même en production. `defaultOrigins()` lit
   `CORS_ALLOWED_ORIGINS`, avertit en production, `resolveOptions()` centralise.
6. **HTTP** — `HttpRequest` enrichi avec `principal` validé ; la Gateway le
   propage aux contrôleurs (plus de `UserContext` hardcodé nécessaire).

## Dogfeeding corrigé

- **IdentityController** (`apps/identity`) : suppression du tableau `SimpleUser`
  hardcodé ; login **fail-closed** (503 sans `AuthManager`, plus de token sans
  vérification mot de passe) ; register/login via `UserService` + `AuthManager` ;
  `getProfile`/`refresh` résolvent le demandeur depuis le JWT (403 si cross-user) ;
  `logout` révoque la session (idempotent). `IdentityServiceProvider` injecte
  `UserService`.
- **PermissionGuard** (`src/shell`) : registre stateless par requête (plus de
  croissance illimitée via `grant` en boucle) ; `authorize([],…)` = route
  publique (autorise guests) ; `src/index.ts` distingue public/protégé via
  `isPublic` + `context.authenticated` (corrige `isPublic ? [] : []`).
- **`src/index.ts`** : `RedisCacheAdapter` mock silencieux remplacé par fallback
  `undefined` + warn ; rate limiter configurable via env ; `corsOptions` via
  `CORS_ALLOWED_ORIGINS` ; `tenant: {id}` conforme à `CompositionContext` ;
  `REGISTERED_PAGE_VIEWS` inexistant remplacé par fallback explicite ;
  import corrigé vers `@mosaix/adapter-cache-redis`.
- **ShellTenantRouter** : n'infère plus l'auth depuis le préfixe `Bearer` ni
  `userId: "user-authenticated"` ; accepte le principal validé, défaut tenant
  unifié `tenant-acme`.
- **ControlPlane** : suppression `admin-1` hardcodé ; exige `req.principal`
  (401 sinon) avec rôle admin.
- **Imperia** : `createPolicy`/`updateSetting`/`executePluginAction`/DLQ/circuit-breakers
  exigent rôle admin ; `recordAuditLog` utilise l'acteur réel ; buffer audit borné
  à 1000 entrées.
- **Spaces Postgres** : `addCapability`/`addTeamMember`/`setCustomDomain` désormais
  en transaction (le `SELECT … FOR UPDATE` hors-tx précédent était inopérant) ;
  `listSpaces` paginé (`limit`/`offset` bornés) ; typages `unknown` durcis ;
  `followSpace` sécurisé. `PostgresUserRepository.list` paginé.
- **Checkout saga** (`apps/commerce`) : ports explicites `PaymentPort`/`InventoryPort`
  (démos marquées, à remplacer par PSP/IMS réels) ; timeout par étape ;
  clé d'idempotence (défaut `orderId`) ; compensations conditionnées à l'état réel ;
  validation `orderId`/`amount`.
- **Tests** : `vitest.config` mappe `@mosaix/auth`/`gateway`/`pipeline` ;
  `identity/index.test` teste le fail-closed + register→login wiré ;
  `control-plane` teste 200 avec principal admin + 401 sans ;
  `otlp-exporter` teste la préservation du batch en échec.

## Résiduel & Décisions Interactives (Appliquées)

### Décisions & Arbitrages
- **DEC-JWT-001 (Fail-fast uniforme)** : `resolveGatewayJwtSecret()` jette une exception en production si `MOSAIX_AUTH_JWT_SECRET` est absent ou < 16 caractères.
- **DEC-BACKUP-001 (db-backup)** : `scripts/db-backup.ts` utilise un vrai `pg_dump` via `execFileSync` (sans shell) et la copie directe pour SQLite, échec bruyant, suppression des dumps mocks.
- **DEC-SESS-001 (Stores persistants)** : `IdentityAdapters` accepte `sessionStore`/`tokenStore`/`credentialStore` (Redis/Postgres) ; défaut in-memory dev/test (`resolveIdentityStores()`).
- **DEC-ADAPT-001 (Adapters Postgres BACs)** : Commerce (`OrderModel`) et Spaces (`DatabasePort`) corrigés ; Solara, Beam, Solidarity, Imperia et Portfolio réalignés (BL-017 à BL-021).
- **DEC-OUTBOX-001 (Outbox worker & publisher)** : `resolveMessageBusDriver()` + `createOutboxMessagingPublisher()` (Kafka/RabbitMQ/Memory) + `startOutboxDaemonFromEnv()` branché au boot (`src/index.ts`) + worker autonome `scripts/outbox-worker.ts`.

### Exécution BL-017 à BL-023
- **BL-021** : `hydrate` typé (`asString`/`asJson`) + route créant un vrai `Vendable` (`apps/portfolio`).
- **BL-017** : Adapter réécrit sur le modèle réel (`actorId`, `publicationType`, `createdAt: Date`, `FollowerRelation`) + pagination (`apps/solara`).
- **BL-018** : Typage `unknown` durci, `listConversations(limit)`, hydratation tolérante JSON (`apps/beam`).
- **BL-019** : Colonnes alignées sur les 7 modèles de solidarité + hydratation `data`-blob typée (`apps/solidarity`).
- **BL-020** : Interfaces exportées, suppression de `unknown[]`, limites bornées (`apps/imperia`).
- **BL-022** : `resolveIdentityStores()` pour Redis/Postgres via env et `databasePort` (`apps/identity`).
- **BL-023 / BL-016** : `startOutboxDaemonFromEnv()` + arrêt gracieux via `gateway.stop` + `scripts/outbox-worker.ts`.
