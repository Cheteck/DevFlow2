# Session Report — 2026-09-14

## Objectif

Évaluer le dogfooding du framework MosaiX par les applications Bounded Context (BACs) et détecter les implémentations qui ne consomment pas les fonctionnalités du framework — notamment celles prétendument "implémentées" dans les phases P1-P8 de production readiness.

## Travaux Réalisés

### 1. Audit de Dogfooding Complet

Mise à jour de `DOGFOODING_GAPS_ANALYSIS.md` avec 7 nouveaux gaps critiques identifiés :

| Gap | Description | Sévérité |
|-----|-------------|----------|
| **GAP-05** | `IdentityController.createJwtToken()` utilise une signature mockée (`"mock-signature"`) au lieu d'HMAC-SHA256. `JwtAuthMiddleware` ne vérifie pas la signature. `@mosaix/auth` `AuthManager` existe mais n'est pas branché dans le boot path. | CRITIQUE |
| **GAP-06** | `AuthorizationEngine` de `@mosaix/core` et `Guard`/`Policy` de `@mosaix/security` sont complètement inutilisés. Permissions hardcodées dans `src/index.ts`. `PermissionGuard` n'existe pas. | CRITIQUE |
| **GAP-07** | Tous les 8 BACs utilisent des repositories InMemory. Aucun adaptateur Postgres n'est implémenté. La base PostgreSQL dans `compose.staging.yml` est inutilisée. | CRITIQUE |
| **GAP-08** | `renderPrometheusMetrics()` retourne des valeurs statiques codées en dur (`1420`, `12`, `5`, `16`). `OTLPTraceExporter.flush()` est un no-op. | CRITIQUE |
| **GAP-09** | `RateLimiter` existe mais n'est pas branché dans le Gateway (`src/index.ts:186-192` ne passe pas `rateLimiterOptions`). | MOYEN |
| **GAP-10** | Headers de sécurité dupliqués : hardcodés dans le pipeline Gateway ET appliqués par `SecurityHeadersMiddleware`. | LEURREUX |
| **GAP-11** | CORS permissif (`access-control-allow-origin: *`) durcit dans le Gateway pipeline. | MOYEN |

### 2. Corrections Appliquées

#### 2.1. JWT HMAC-SHA256 (GAP-05 — partie technique)
- `apps/identity/src/infrastructure/identity-controller.ts:36-51` : Remplacement du `"mock-signature"` par `crypto.createHmac("sha256", JWT_SECRET)` avec `base64url` encoding
- `src/shell/middleware/jwt-auth-middleware.ts:24-47` : Ajout de la vérification de signature HMAC-SHA256 avec `crypto.timingSafeEqual` (protection contre timing attack)

#### 2.2. Métriques Prometheus réelles (GAP-08 — partie technique)
- `packages/telemetry/src/otlp-exporter.ts:56-69` : Remplacement des valeurs statiques par un état mutable (`MetricsState`) avec `incrementRequestCounter()` et `setCompositionMetrics()`
- `OTLPTraceExporter.flush()` : Implémentation réelle de l'export HTTP POST vers l'endpoint OTLP

#### 2.3. RateLimiter branché (GAP-09)
- `packages/gateway/src/gateway.ts` : Ajout de `incrementRequestCounter(response.statusCode)` dans le flow de requête
- `src/index.ts:186-194` : Branchement de `RateLimiter` avec `RedisCacheAdapter` via `REDIS_URL` env, fallback in-memory si Redis absent
- `packages/gateway/package.json` : Ajout dépendance `@mosaix/telemetry`
- `packages/gateway/tsconfig.json` : Ajout référence projet `@mosaix/telemetry`
- `package.json` (root) : Ajout deps workspace `@mosaix/adapters/cache-redis`, `@mosaix/gateway`, `@mosaix/http`, `@mosaix/ports-cache`, `@mosaix/telemetry`

#### 2.4. Headers de sécurité dédupliqués (GAP-10)
- `packages/gateway/src/gateway.ts` : Suppression des headers hardcodés du pipeline (x-content-type-options, x-frame-options, access-control-allow-origin) — conservé uniquement via `SecurityHeadersMiddleware`

#### 2.5. Backlog mis à jour
- `.project/backlog/active-backlog.md` : Ajout de 6 items de backlog (BL-010 à BL-015) pour les lacunes non corrigées

## Décisions Prises

- **Décision** : Utiliser `node:crypto` (HMAC-SHA256) pour la signature JWT plutôt que `jsonwebtoken` — évite une dépendance externe, utilise uniquement le standard Node.js natif
- **Décision** : Garder le fallback in-memory pour `RateLimiter` quand Redis est absent — compatibilité dev local sans infrastructure
- **Décision** : NE PAS corriger GAP-07 (Postgres adapters) dans cette session — c'est une entreprise large (8 adaptateurs à créer, migrations à écrire), priorisée au backlog comme BL-012
